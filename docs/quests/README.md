# 퀘스트 기획

출처를 확인한 장소·기록을 바탕으로 퀘스트를 기획하는 폴더입니다. 지금은 작성 규칙만 준비하며 실제 퀘스트, 관광 설명, 역사 서사를 확정하지 않습니다.

## 기본 원칙

- 초기 MVP 후보는 장소 2~3곳입니다. 조사 결과에 따라 선정합니다.
- 검토 중인 시대 흐름은 조선 전기 → 조선 후기 → 일제강점기 → 전후 → 현재입니다. 확정된 역사 구분이나 필수 스테이지가 아닙니다.
- 실제 역사적 주장, 게임을 위한 허구·연출, 미검증 아이디어를 구분합니다.
- 미션이 끝나면 기억 조각을 얻고 지도를 복원하는 흐름을 검토합니다. 근거 자료가 확보된 경우에만 과거·현재 비교를 제시합니다.
- 출입 제한 구역 접근, 위험한 촬영, 타인 얼굴·개인정보 수집을 유도하지 않습니다.
- 문서상 기획 단계에서는 얼굴 사진, 실제 사용자 업로드, 위치 이력을 저장하지 않습니다.

파일명 예시: `draft-장소명-퀘스트명.md`. 검증 전에는 `draft`로 표시합니다.

이 필드들은 향후 출처를 추적하기 위한 **문서 작성 제안**입니다. DB 스키마나 API 계약으로 확정한 것이 아닙니다. 확인하지 못한 값은 비워 두거나 미확인으로 표시합니다.

## 실제 사진과 AI 이미지 구분

- 실제 과거 사진은 기록 출처와 촬영 시기를 확인합니다. 현재 사진도 촬영자와 이용 권리를 기록합니다.
- AI 생성 이미지는 역사적 증거로 사용하지 않습니다. 사용자 화면에도 `AI 생성 이미지 · 역사적 재현을 위한 연출`처럼 명확하게 표시하는 방향을 검토합니다.
- AI가 상상한 건물·복식·사건을 실제 자료와 섞어 사실처럼 설명하지 않습니다.
- 비교 화면에는 원문 출처와 불확실성을 함께 보여 주는 방식을 설계합니다.

## AI 판정의 다음 개발 방향

초기 세팅에는 AI 기능을 구현하지 않습니다. 다음 단계에서 사진 판정 요청과 결과 형식을 먼저 합의하고, 게임 진행 로직과 판정 구현을 분리합니다.

1. 외부 API·API 키가 없는 mock 판정으로 성공·실패·재시도를 테스트합니다.
2. 판정 구현을 교체할 수 있는 작은 인터페이스를 두는 방향을 검토합니다.
3. 실제 AI 도입은 정확도, 비용, 응답 시간, 사진 처리·보관 정책을 확인한 뒤 결정합니다.
4. 판정 실패·네트워크 오류·촬영 불가 시 진행 방식도 함께 설계합니다.

mock은 데모와 개발을 위한 가짜 응답입니다. 실제 사진을 분석한 결과처럼 표시하지 않습니다.
