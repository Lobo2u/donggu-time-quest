# 동구 TIME QUEST

2026 대전 로컬창업 해커톤을 준비하는 도보 탐방형 웹 프로젝트입니다.
대전 동구의 장소를 걸으며 시대별 미션을 수행하고, 역사 기록과 기억 조각을 모아 미완성 지도를 복원하는 경험을 구상합니다.

현재는 **문제 조사와 프로젝트 초기 설정 단계**입니다. 해결할 문제, 이용자, 장소, 시대 구성은 조사와 현장 방문을 거쳐 정합니다. 아래 MVP와 일정은 구현 완료 목록이 아닙니다.

## 1. 프로젝트 방향

### 아직 조사 중인 문제

동구를 방문하거나 생활하는 사람이 장소의 역사와 현재 모습을 어떤 방식으로 접하는지 살펴봅니다. 탐방 과정에서 실제로 불편한 점과 필요한 경험을 확인한 뒤 문제를 구체화합니다.

우선 확인할 질문은 다음과 같습니다.

- 누구에게 필요한 서비스인가? 주민, 방문객 등 후보 이용자의 상황은 어떻게 다른가?
- 이용자는 동구의 장소를 어떻게 찾고, 어떤 경로로 걸어 다니는가?
- 장소의 역사나 이야기를 접할 때 무엇이 어렵거나 아쉬운가?
- 미션과 지도 복원이 실제 탐방 동기와 이해에 도움이 되는가?
- 안전하게 걸을 수 있는 동선과 방문 가능한 장소는 어디인가?

지역 조사, 이용자 확인, 현장 방문 결과는 `docs/research/`에 기록합니다. 아직 확인하지 않은 문제를 지역의 확정된 문제처럼 쓰지 않습니다.

### 탐방 콘셉트

처음에는 불완전한 회색조 지도가 보입니다. 이용자는 대전 동구의 장소로 걸어가 시대별 미션을 수행합니다. 미션을 마치면 역사 기록이나 기억 조각을 얻고, 해당 구역의 지도가 점차 복원됩니다.

시대 구성의 후보는 **조선 전기 → 조선 후기 → 일제강점기 → 전후 → 현재**입니다. 최종 구성이 아니며, 확인 가능한 자료와 실제 장소의 연관성을 바탕으로 조정합니다.

역사 설명과 과거 이미지는 출처를 확인한 자료를 사용합니다. 사실과 게임의 창작 설정을 구분하고, 자료가 없는 사건이나 이야기를 만들어 역사적 사실처럼 제시하지 않습니다.

## 2. 예비 MVP 범위

추후 MVP는 도보로 연결할 수 있는 **장소 2~3곳**을 대상으로 검토합니다. 장소 선정과 세부 기능은 조사 결과에 따라 바뀔 수 있습니다.

### 전체 이용 흐름

1. **지도 확인**: 회색조의 미완성 지도에서 탐방할 장소를 확인합니다.
2. **장소·퀘스트 선택**: 장소와 연결된 시대, 이동 안내, 퀘스트를 확인합니다.
3. **현장 이동·미션 확인**: 해당 장소로 걸어가 수행할 미션을 읽습니다.
4. **사진 촬영 또는 업로드**: 미션의 대상이 보이도록 사진을 촬영하거나 올립니다.
5. **대상 판정**: 사진에 미션 대상이 있는지 확인합니다. 첫 구현은 실제 AI 호출 없이 모의 판정(mock)으로 흐름을 검증합니다.
6. **미션 성공 확인**: 판정 결과를 확인합니다. 실패하거나 확인이 어려운 경우에는 안내를 보고 다시 시도하는 흐름을 검토합니다.
7. **기억 조각 획득**: 성공한 미션과 연결된 역사 기록이나 기억 조각을 확인합니다.
8. **지도 복원**: 완료한 장소 또는 구역의 지도가 복원됩니다.
9. **과거·현재 비교**: 출처가 확인된 과거 자료와 현재 장소를 비교합니다.

사진 판정은 나중에 화면·퀘스트 진행과 분리된 인터페이스로 설계할 예정입니다. 모의 판정으로 먼저 연결하고, 필요성과 범위를 확인한 뒤 실제 AI 서비스 교체 여부를 결정합니다. 현재 단계에서는 실시간 AI API를 연결하지 않습니다.

### 이번 초기 설정에 포함하는 것

- Vue 3 + Vite 기반 JavaScript 프런트엔드의 기본 실행 구조
- FastAPI 백엔드와 상태 확인 API
- 의존성 고정 파일과 기본 점검 명령
- 조사·회의·퀘스트 문서를 둘 위치
- 팀 작업과 브랜치 사용 안내

지도, 장소 선택, 미션, 사진 처리, AI 판정, 기억 조각, 지도 복원은 **아직 구현하지 않습니다**.

### 이번 단계에서 제외하는 것

- 결제, SNS 기능, 복잡한 AR, NFC
- 네이티브 앱, 복잡한 관리자 기능
- 자체 AI 모델 학습, 실시간 AI API 연동
- 불필요한 회원가입과 로그인
- 데이터베이스 설계
- 특정 지도 제공업체의 확정·연동
- 출처 없는 역사 설명이나 장소 콘텐츠 제작

필요한 기능이 생기면 문제와 MVP 검증에 필요한지 먼저 논의합니다.

## 5. 로컬 실행

### 준비

- Git
- Node.js **24.x 권장**. 22.x를 쓰는 경우 **22.12 이상**을 사용합니다.
- Python **3.12**
- uv ([공식 프로젝트 사용 안내](https://docs.astral.sh/uv/guides/projects/))

루트의 `.nvmrc`는 Node.js 24를 기준으로 합니다. 이미 nvm을 쓰고 있다면 루트에서 `nvm use`로 버전을 맞출 수 있습니다. Windows의 버전 관리 도구는 사용 중인 도구의 방식에 맞춰 Node.js 24를 선택합니다.

설치된 버전은 다음 명령으로 확인합니다.

```bash
node --version
npm --version
python --version
uv --version
```

Windows에서 `python` 명령이 잡히지 않으면 `py -3.12 --version`으로 설치 여부를 확인할 수 있습니다. 이후 uv 명령은 운영체제에 관계없이 같습니다. 가상환경을 따로 활성화하지 않아도 `uv run`이 프로젝트 환경을 사용합니다.

### 저장소 받기

아래 주소는 프로젝트에 지정된 저장소입니다. 먼저 GitHub에서 저장소 접근 권한과 초기 코드 등록 여부를 확인하세요. 접근되지 않으면 팀 담당자에게 확인합니다.

```bash
git clone https://github.com/Lobo2u/donggu-time-quest.git
cd donggu-time-quest
```

현재 저장소의 기본 브랜치는 `master`입니다. 이 초기 세팅은 `develop`에 반영하는 방식으로 준비합니다. 팀 개발에 참여할 때는 실행 전에 [CONTRIBUTING.md](CONTRIBUTING.md)의 `develop` 확인·갱신 절차를 따릅니다. 원격에 `develop`이 아직 없다면 초기 설정 담당자에게 확인합니다.

기존 Copilot 초안의 React·Express 구성은 이번 Vue·FastAPI 구성으로 교체합니다. 이전 내용은 Git 이력에서 확인할 수 있으며, 기존 MIT 라이선스는 유지합니다. 설치·실행 명령은 루트가 아닌 각 `frontend/`, `backend/` 폴더에서 실행합니다.

### 프런트엔드

저장소 루트에서 실행합니다.

```bash
cd frontend
npm ci
npm run dev
```

기본 접속 주소는 `http://localhost:5173`입니다. 포트가 사용 중이면 Vite가 안내하는 주소를 확인하세요.

`npm ci`는 `package-lock.json`에 기록된 버전으로 설치합니다. 설치 오류를 피하려고 잠금 파일을 지우거나 임의로 새로 만들지 말고, Node.js 버전과 저장소 상태를 먼저 확인합니다.

### 백엔드

**새 터미널을 열고 저장소 루트에서** 실행합니다. 프런트엔드 터미널은 그대로 둡니다.

```bash
cd backend
uv sync --frozen --group dev
uv run uvicorn app.main:app --reload
```

- 상태 확인: `http://127.0.0.1:8000/health`
- 정상 응답: `{"status":"healthy"}`
- API 문서: `http://127.0.0.1:8000/docs`

`uv sync --frozen --group dev`는 저장된 잠금 파일을 변경하지 않고 개발용 의존성까지 설치합니다. `uv.lock` 관련 오류가 나면 파일을 삭제하기보다 담당자와 의존성 변경 여부를 확인합니다.

각 서버는 해당 터미널에서 `Ctrl+C`로 종료합니다.

### 환경변수와 비밀값

현재 기본 실행에는 외부 AI 서비스의 API 키가 필요하지 않습니다. `.env.example`은 필요한 환경변수 이름과 안전한 예시를 공유하기 위한 파일입니다.

추후 환경변수가 필요해지면 사용 위치를 정한 뒤 예시 파일을 참고해 로컬 `.env`를 만듭니다. 실제 API 키, 비밀번호, 토큰은 `.env.example`, 코드, 문서, 커밋, PR에 넣지 않습니다. `.env`도 커밋하지 않습니다.

## 6. 변경 후 확인

프런트엔드는 `frontend/`에서 실행합니다.

```bash
npm run check
npm run build
```

`check`는 기본 화면의 smoke test를 실행하는 명령입니다. `build`는 배포용 빌드가 가능한지 확인합니다. 두 명령만으로 모바일 사용성이나 전체 이용 흐름 검증이 끝나는 것은 아닙니다.

백엔드는 `backend/`에서 실행합니다.

```bash
uv run pytest
uv run ruff check .
uv run ruff format --check .
```

테스트, 코드 규칙, 서식을 각각 확인합니다. 서식 검사에 실패하면 변경 내용을 확인하며 수정하고 다시 실행합니다. PR에는 실행한 명령과 결과를 적습니다.

## 9. 함께 작업하기

협업에서 역할을 설명할 때는 `feature/* → develop → main` 흐름을 기준으로 합니다. 다만 현재 저장소의 기본 브랜치 이름은 `master`이므로 실제 반영 대상은 `feature/* → develop → master`입니다. `main`으로 이름을 바꾸거나 새 기준 브랜치를 만드는 일은 팀에서 별도로 결정하며, 이번 초기 세팅에서는 진행하지 않습니다. `master`와 `main`에는 직접 push하지 않습니다.
